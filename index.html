Approach

How I Work

Risk-Based Thinking

Effort follows risk. I identify where a failure would have the biggest impact on quality, data or the business, and focus review, testing and controls there first.

Traceability by Default

Requirements, tests, results and decisions should link to each other. When an auditor asks "why?", the answer is already documented.

Data Integrity First

I treat ALCOA++ as a design requirement, not a final check. Records should be attributable, legible, contemporaneous, original and accurate, and complete, consistent and available when needed.

Root Cause Mindset

I fix causes, not symptoms. Deviations and audit findings get a structured root cause analysis, and each CAPA is judged by whether it actually prevents recurrence.

Involved Early

Ambiguity is cheapest to fix at the requirements stage. I get involved early and ask the hard questions before go-live, not after.

Automate the Repetitive

If a quality task is frequent, manual and rule-based, it is a candidate for automation. I use Python and AI-assisted tools to free time for work that needs human judgment.
